# 02 - EXE internals

Everything known about the inside of `CivilizationV_DX11.exe` (and, where derived, its DX9 `CivilizationV.exe` and
Tablet `CivilizationV_Tablet.exe` siblings) that matters for keeping the 32-bit EXE as a shell: the
`[DisableSystems]` switches and the two masks behind them, the static world-system objects and why five of them
crash when switched off, the DLL-side stubs that remove them (Split 1 / Split 2), the camera and picking state a
64-bit server needs each frame, the engine allocator and the large blocks it owns, the fixed-size buffers that
overflow (4 MB game-to-UI queue, 1 MB UI draw list), the measured launch-to-play timeline, and a single sorted
address table. All work was done between 2026-09-21 and 2026-11-10 by static analysis (llvm-objdump, Ghidra 12.1.4
on a copy of the EXE), minidumps, live probes on the huge save `VP8P-HUGE_0350` (t350, cp+vp+eui, Release 5.4.8 DLL)
and DLL-side instruments that write only import slots or heap data (Steam CEG hashes `.text`). Addresses are DX11
VAs at ImageBase 0x400000 (TimeDateStamp 0x546CD0A8) unless marked; `crashes.log` "Location (in file)" values are
file offsets (VA = offset + 0x400C00). The DLL is `CvGameCore_Expansion2.dll`, always called "the DLL" here.
