# 06 - Tooling and workflows

Scope: how to build and install the VP DLL, start, drive, observe and stop the game without taking the owner's focus,
test DLL changes headless, set up parallel game instances, reverse-engineer the EXE, and switch on the DLL's
opt-in instruments - so that nobody re-derives what earlier sessions (2026-09-05 to 2026-11-10) already paid for.
Everything here is copied or synthesised from `research/sources/`; nothing was re-run. Where sources disagree, the
files say so. Paths are the owner's machine (Windows 11 Home 26100, i9-13900KS, RTX 4080, three monitors).

## Hard safety rules

```
+------------------------------------------------------------------------------------------------------+
| 1. Never create junctions (or other links) into the game install. A VP_MODPACK junction under         |
|    Program Files could be created but its removal was denied to the agent (2026-10-01); if a link is  |
|    ever unavoidable, settle the undo with the owner first and remove it in the same session.                 |
| 2. Never kill the game while it writes an autosave: the turn's AutoSave_Post_NNNN is written at the   |
|    same instant the DLL logs the turn, and a kill leaves a truncated .Civ5Save that crashes the loader |
|    later (both the target save and the overshoot save, target+1).                                     |
| 3. Never delete or overwrite the owner's saves. Experiments only read saves; the game may write its own      |
|    autosaves. (vp_game.py's pruning touches only AutoSave_* written after its own launch.)            |
| 4. Back up, then restore by hash: config.ini, GraphicsSettingsDX11.ini, the installed                  |
|    CvGameCore_Expansion2.dll and the front-end Lua. Verify SHA-256 after restoring (reference values   |
|    of 2026-11-09: config.ini 7b53b17c3935702d..., DLL 262AEE88...). Leave no marker files in           |
|    <install>\crashlogs.                                                                                |
| 5. Stop the game with `vp_modgame.py stop` (or the skill's own stop), not taskkill. Read note below.  |
| 6. `vp_modgame.py launch --mods ...` runs with --exclusive by default: every other mod is left         |
|    DISABLED in the mods database afterwards. Tell the owner, or re-enable.                                    |
| 7. Never take the owner's focus: launch through civ_bg.py (guard loaded before the first instruction);       |
|    never use --no-guard or late injection while the owner works; never use civ_ui.py's focus/SendInput path  |
|    on a background game.                                                                               |
| 8. Never pass NO_* / NUM_* enum values or unvalidated IDs through the Lua channel (a failed ASSERT     |
|    freezes the game; Cancel/Enter on the dialog exits it). Never call window-touching engine functions |
|    from the channel (deadlock); use a one-shot Events.LocalMachineAppUpdate handler.                   |
+------------------------------------------------------------------------------------------------------+
```

Note on rule 5: the sources say to stop with `vp_modgame.py stop` / `vp_game.py stop`, but none of them shows how
`vp_modgame.py stop` ends the process, and `civ_bg.py stop` (read in full) calls psutil `terminate()` and `kill()`
after 15 s - i.e. a hard termination. Neither waits for an autosave by itself, so rule 2 still has to be honoured
by timing: stop while the human's turn is active and the newest autosave's size and mtime have settled
(`vp_game.py` records this as `final_save_settled`). Unverified beyond that.
