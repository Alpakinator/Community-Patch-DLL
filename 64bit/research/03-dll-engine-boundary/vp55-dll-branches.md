## 4. Save format on 5.5 (for D239 and the tier saves)

Upstream 0848d52cc (#13643, 2026-11-24, in Release-5.5) gives each player its own ID counter for cities, units and
armies and saves it with the player; its message says saves made before it do not load `[C]`. So **no 5.4.8 save loads
in a Release-5.5 DLL**, x86 or x64: every reference and tier save is made again on 5.5 (0766, 0771). Within 5.5 the
x64 build writes the x86 format as long as section 6's identity check passes. a82a49797 (#13627, sync counters) changes
no save field `[C]`.

## 7. How to redo it

1. A fork clone of your own (runbook 1.1), `git -C <clone> fetch upstream tag Release-5.5`, `fetch origin x64-0.1b
   i0-0.1b export-e5-dll i0-release-master-ba8aafdc-r2`.
2. i0: a worktree of Release-5.5 on a new branch; `python -I tools/x64-dll/evidence/0764/pick.py --wt <worktree>
   --series tools/release/series/carry.tsv --branch i0 --json <a dry run's branches.json> [--from <row>] [--drop <row>]`
   picks row by row and stops at each conflict (section 3 says how each was resolved). Or simply
   `python -I tools/release/branches.py --fork <clone> --base Release-5.5 --series tools/x64-dll/evidence/0764/carry-Release-5.5.tsv
   --name <name> --compare-i0 origin/i0-vp55 --compare-x64 origin/x64-vp55` (about 20 s).
3. x64: `git cherry-pick -x 6f5f1cf55 03ce5ed6e 58a8ce863` onto i0-vp55.
